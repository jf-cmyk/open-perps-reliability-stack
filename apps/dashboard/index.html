How It Works

Reviewer integration flow

Built for open-source reliability review first: adapters and fixtures become proof-pack evidence before any live infrastructure or commercial service is considered.

01

Fixture and Adapter Setup

Define read-only protocol fixtures, public guardrail labels, expected account shapes, version gates, and sample market state.

02

Risk and Data Quality Validation

Apply oracle confidence, staleness, divergence, missing data, and adapter mismatch policies to every case.

03

Reviewer Proof Pack

Publish dry-run replay outputs, guardrail DQ gates, reason-code counts, and static evidence for grants, maintainers, and integrators.

04

Source Authority Gaps

Use Jupiter onchain IDL for layout decode and local role-map probes, while keeping request/fulfillment evidence candidate-only until before/after state gates land.

Protocol Gates

What is proven, blocked, and next

The MVP has useful reviewer evidence already, but each protocol still earns claims independently. Anything past public read-only and dry-run evidence stays blocked by design.

Drift
Partial proof

Guardrail packages and bounded liquidation-history scans are public. A historical reconstruction still needs a source-backed transaction candidate.

Jupiter
Layout decoded

Target discovery and onchain-IDL Position / PositionRequest decode are visible. Verified pairing and replay still need lifecycle role maps or fixtures.

Phoenix / Rise
Source pinned

Telemetry and Hawkeye planning are public. Account decode, oracle-input identity, trader monitoring, and replay are not claimed.

Runtime
Benchmark ready

The slot-regime activation boundary is public for normalization. It does not claim faster landing, lower skips, or validator performance gains.

Access Boundaries

Review surfaces stay public and inert

Private Access
No protected route data

Static pages do not expose account-specific route intelligence, privileged wallets, or off-chain strategy inputs.

Connectivity
No RPC dependency

The public demo renders from embedded fixtures, so it works without cluster access or authenticated services.

Dry-run Gate
No signing or live execution

The replay layer is deliberately dry-run only and records blocked outcomes for reliability review.

Decode Worker
Local-only contract

The read-only decode worker is documented as a one-shot local command shape; Railway remains a static proof-pack service. Read the Drift scan boundary.

OSS and Commercial Tracks

Clear boundaries for open reliability work
